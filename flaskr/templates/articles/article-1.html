My most memorable CSS misconceptions

I have been writing CSS for more than twenty years. For a short period of time , about ten years ago, it was my main daily focus; it was then that I learned most about it. For the rest of the time, as a GIS developer, a full-stack Web developer and a front-end developer, CSS was never my main focus. Maybe for this, after so many years, it's a language that I still do not feel I master. Or maybe that is just CSS, it will always defy you, no matter how much you put into it.

Anyhow, here is a list of some aspects of the language that got me tripped up over the years.

z-index

Who didn't stumble upon this one at some point? You set a ridiculously high z-index value on an HTML element, only to realise, with great frustration, that it doesn't work, the element refuses to make its way up the stack.

One things I learned pretty soon is that the element I am targeting needs to be positioned relative or absolute. And only much later I found the time to read and understand that things are a bit more nuanced than that. That in order to work, a z-index needs to create a stacking context and that this can be done in many ways, the permutations are multiple.

So, applying a z-index value to an element in normal flowwill not create a stacking context. That did not make much sense to me in the days, but feels pretty obvious now. Normal flow is the default layout for HTML documents, the original layout, where blocks of text flow from top to bottom, without never overlapping. Hence, applying a z-index property to a block of text in normal flow made no sense, but it did if you removed it from the flow by applying a relative or absolute position.

One last thing to remember is that z-index values work within their own stack context, they will not influence other contexts. If something is not working as expected within a complex layout, then this might be the reason.
